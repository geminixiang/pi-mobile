# Grok Bot 與 pi mobile

調查日期：2026-11-04。對象：Grok Bot Android 1.19.0（3023），在 S24 上逐頁看過，之後實際交辦任務（第 3 節），另外對照一個自架的 MCP 信箱服務的改版計畫。問題：使用者覺得 Grok Bot「輕鬆又簡單」，它做對了什麼、pi mobile 該借哪些。

結論先講：

- Grok Bot 的輕鬆來自**對話裡的互動元件**，不是功能多：Bot 先開口，每個問題附可以一點就回的選項，會動到外界的動作是一張卡、按了才執行。大多時候使用者只點，不打字。
- pi mobile 的能力（手機原生、自動化、電腦、MCP）比它廣，但每一步都要使用者先開口、自己去設定裡找。
- 最先做的是**問題卡**：Bot 提問時附 2–4 個選項。開場引導、對話裡連服務、提議自動化都建在它上面。

## 1. 第一次使用的流程

1. 新 Bot 自我介紹，接著一張問題卡問「你想怎麼稱呼我？」，卡上有一個預設答案，點一下就回答；回答後對話裡多一行灰字「已重新命名為 …」。
2. 說明能做什麼（不在時也會在自己的電腦上繼續工作、能像你一樣使用連接的 App），然後在對話裡放一張 Gmail 連接卡，下面寫「進行變更前一定會先詢問你，可以隨時中斷連線」。
3. 連好後列出能用它做的四件事，再問「要我幫你找幾件可以協助的事嗎？我只會讀取最近的郵件，不會寄出、刪除或更改任何東西」，附一個按鈕「建議第一個任務」。
4. 從信裡找出幾件事，用問題卡問「要從哪件開始？」；需要細節時給 A/B/C/D 四個選項，下面一行「或在下方聊天中回答」。
5. 要寄信時，對話裡是一張可以展開的「郵件」卡，寫好全文和收件人，使用者按「傳送」才寄出，之後卡片顯示「已傳送 · 收件人」。
6. 事情做完，順勢問「要我每天早上幫你看信箱嗎？」，點「好」後對話裡一行「Created routine」，再用一段話說它之後會做什麼、沒有重要的事就不打擾。

## 3. 實際用過之後

2026-11-04 在 S24 上實際交辦任務（下面都是跑過看到的；Bot 對自己的說明是它自述，沒有另外驗證）。

### Agent 的樣子

- **一個 Bot 是一個隊友，不是一段對話**。它自述：一台雲端電腦（瀏覽器、跑程式、做檔案）、接上的服務、另外保管的記憶；不在時只做排程，不自己翻東西。
- **團隊模型**（第二個 Bot 自述，記憶那段實測對了）：關於使用者本人的記憶共用，每個 Bot 有自己的聊天、個性和記憶；同一台電腦，檔案、工具、瀏覽器登入共用，但各有自己的桌面。跟 pi mobile 的 global／bot 記憶幾乎一樣。
- **Bot 之間直接傳訊息**：請一個 Bot 去問另一個，對話裡是灰字事件行「已傳送給 Haru」「訊息來自 Haru」，回覆後主動補「如果你問的是另一份…」。另一邊的對話收成一行「2 條訊息，與 Kumo」。
- **服務授權和瀏覽器登入是兩件事**：連結走官方授權（API，快、穩、可撤銷），在 Bot 電腦上登入是像人一樣開網頁（做 API 做不到的事，登入狀態留著）。要開 GitHub 登入頁時，它同時放一張 GitHub 連接卡，把人導向比較好的那條路。
- **老實交代**：做完先說哪裡沒做、哪些查不到，頁面上標「未確認」，最後問想補哪一塊。
- **不信使用者的「我完成了」**：交還電腦後自己再看一次畫面，說「還停在登入頁，要再交給你一次嗎」，並附上截圖。

### 工作時的畫面

- **先回一句，再做事**：「好，我先查…」，長的任務再說「大概要幾分鐘，做好就傳給你」，人可以離開。
- **不顯示工具步驟**：只有一行會動的頭像，加上這件事的名字（「製作比較網頁」「查詢台北天氣」），久了加「· 2 分鐘」。標題列頭像多一個綠點。沒有腳本、沒有 JSON。
- **表情回應**：Bot 在使用者的訊息上按 👍、✅，代替一句「收到」。
- **Bot 有顏色**：頭像、語音鍵、使用者氣泡都跟著 Bot 的顏色走，一眼知道在跟誰說話。

### 對話裡的元件

| 元件 | 樣子 | 之後 |
|---|---|---|
| 問題卡 | 題目、A–D、✕ 忽略問題、「或在下方聊天中回答」 | 使用者打字時選項變淡 |
| 頁面卡 | 頁面縮圖、標題、類型；點開是底部拉起的全頁，右上分享 | 收進 Bot 的資料庫 |
| 郵件卡 | 主旨、寄件者、收件者、抄送、內文、簽名都在卡上；「需要核准 ▾」「捨棄」「傳送」 | 收成「郵件 已傳送 · 收件人」，點開看全文 |
| 接手卡 | 「請登入…完成後按交還」、電腦畫面縮圖、「跳過／我完成了／接管」、說明登入會留在哪 | 收成「電腦 完成 · …」 |
| 接手畫面 | 全螢幕遠端桌面，下方剪貼簿、我完成了、鍵盤；⋯ 有觸控板模式，? 有手勢說明 | |
| 權限卡 | 「聯絡資訊 · 某某的 S24 ·〔允許〕」，寫明哪台裝置，按了才跳系統權限 | 「✓ 已允許」 |
| 天氣卡 | 原生卡片：現在、逐時、逐日、攝氏／華氏切換、資料來源和更新時間 | |
| 圖片 | 直接內嵌 | |
| 事件行 | 「Created routine」「Deleted routine」「已傳送給…」，一行灰字 | |

**分級信任放在動作上**：郵件卡的「需要核准 ▾」有三項：允許收件者、需要核准、關閉草稿。信任不是全有全無，而是「這個收件者以後不用再問」。

### 其他

- 第二個 Bot 不重來一次介紹，直接問「想先從哪件事開始」，選項是任務類別。
- 首頁像聊天 App：主要 Bot 放大，其他 Bot 一列一個，有最後一則訊息和時間。
- 例行任務建好後說清楚時間（前後 15 分鐘）、要做什麼、第一次是哪天。
- 記憶沒有介面，👍 加一句「記下了」。
- 刪除 Bot 用確認框，說明會永久刪除對話。

## 4. 改進清單

依順序排，前面的讓後面的做得出來。

### 對話裡的互動

1. **問題卡**：Bot 用一個工具提問，附 2–4 個選項，點一下就回答，也能直接打字。已做：`ask_user`，擴充 `interaction`（`src/interaction/`）；第 2–6 項的互動元件都放進同一個擴充。
2. **新 Bot 先開口**：問稱呼、說明能做什麼、提議連一個服務。
3. **對話裡連服務**：連接卡片直接出現在回答裡，寫明改動前會先問；連好後列出能用它做的事。現在要到 設定 › MCP。
4. **動作前的確認卡**：寄出、送出這類動作改成對話裡一張可以展開看全文的卡，按下才執行，之後顯示結果。取代另外跳出的確認框，也是 MCP elicitation（第 17 項）的畫面。
5. **做完順勢提議自動化**：點一下建好，對話裡留一行，說清楚之後會做什麼、何時不打擾。
6. **系統事件行**：改名、建立自動化、連好服務時，對話裡留一行灰字。

### Bot 和設定

7. **權限規則**：一律詢問和直接允許兩組規則，加一個自動審核開關。
8. **服務目錄**：依類別列出可連的服務和推薦；手機本身的能力寫「第一次需要時會詢問」。
9. **每個 Bot 的通知開關**：完成或等你處理時通知，放在 Bot 面板。
10. **搜尋**：一次搜訊息、Bot、檔案、自動化。
11. **Bot 的檔案庫**：Bot 做出來的頁面和檔案集中在 Bot 面板。
12. **電腦即時畫面和接管**：看 Bot 在電腦上做什麼，按「接管控制」改由人操作；從快照重置。
13. 次要：群組聊天（多個 Bot）、匯入其他助理的記憶、Bot 造型和顏色、用量（pi mobile 用使用者自己的 key，改成花費）、保管庫（牽涉安全，另外評估）。

### MCP

14. pi-mcp 升到 1.5.0（OAuth 只接受 `http:`、`https:` 的授權網址）。
15. 呼叫回「找不到工具」時重新連線、換上新清單，再告訴 Bot 改用新名稱。App 每次開啟都會重抓清單（`src/agent/runtime.ts` 的 `mcp.refreshAll()`），只有開著時伺服器部署新版才會遇到。
16. 照伺服器的 `ttlMs` 快取清單；能讀 `resource_link`，把一封信加進對話（pi-mcp 已有 `readResource`）。
17. 伺服器在寄信前要求確認（2026-07-28 的 `input_required`）：已做。pi-mcp 還不支援 2026-07-28，`src/agent/mcp-stateless.ts` 只替 `tools/call` 補上新版（先問 `server/discover`，不支援就照舊走 pi-mcp），確認卡在 `src/interaction/FormCard.tsx`。別人怎麼做互動卡見 [interaction-cards.md](interaction-cards.md)。
18. 伺服器提供的 prompts（整理收件匣、回覆這封信）當成輸入框的快捷動作；pi-mcp 目前沒有 prompts API。

### 實際用過之後新增

19. **工作時只顯示一行**：Bot 給這件事一個名字，畫面只有會動的記號和名字、已用時間，工具步驟收起來，要看才展開。這是跟 Grok Bot 感覺差最多的地方。已做：`codemode` 的 `title`、`src/app/step-runs.ts`、`WorkLine`。
20. **先回一句再做事**：提示裡要 Bot 動手前先說一句，久的任務講大概多久。已做。
21. **結果卡**：工具有結構化輸出時畫成原生卡片，先做天氣；頁面（`.html`）畫成帶縮圖的卡。放進 `interaction`。
22. **做完老實交代**：提示裡要 Bot 說沒做到什麼、查不到什麼，不確定就標明。
23. **交還後自己驗證**：瀏覽器 `hand_over` 交還後，Bot 再看一次畫面才繼續，結果不對就再問一次。
24. **手機權限卡**：第一次用到才在對話裡問，按了才跳系統權限，現在要使用者自己去設定開。
25. **動作上的分級信任**：確認卡加「以後這個收件者不用問」，存成權限規則（第 7 項）。
26. **表情回應**：Bot 在使用者訊息上按表情，取代「收到」。
27. **Bot 的顏色**：頭像、氣泡、送出鍵跟著 Bot 的顏色；pi mobile 的 Bot 是像素頭像，要先想怎麼跟 DESIGN.md 合。
28. **Bot 之間傳訊息**：一個 Bot 問另一個，雙方對話留事件行。
29. **把人導向比較好的路**：要用瀏覽器登入一個有 MCP 或 API 的服務時，先提議連接。
