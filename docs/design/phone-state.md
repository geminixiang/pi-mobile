# 手機的狀態：每一類都能讀、也能改

2026-10-26。起因：使用者說「一連上當前 Wi‑Fi，幫我把鈴聲打開，但不要太大聲」，Bot 讀得到「震動」，卻沒有工具改鈴聲和音量，也不知道現在連的是哪個 Wi‑Fi。這不是缺一個工具，是缺一條原則。

## 原則

1. **手機上的每一類東西，Bot 能讀它的狀態，也能改它**。讀和改放在同一個工具，用 `action`（或 `mode`）分，第一個值是 `status`（`docs/tools.md` § 名稱）。
2. **先用原生 API；無障礙服務只是 fallback**。只支援 Android 16 以上（`minSdkVersion` 36，2026-10-26 起），所以「原生做不做得到」以 Android 16 為準，不為舊版寫另一條路。
3. **原生不准改的，才走系統給的開關畫面**：工具打開那個面板；手機畫面（無障礙服務）開著時，工具自己找到開關按下去，再讀一次狀態確認，然後關掉面板；沒開時，面板留在畫面上讓使用者按，結果寫明「使用者按了才會改」。
4. **本質上唯讀的不硬做**：感測器、螢幕使用時間、位置、通話紀錄是紀錄或量測，沒有「改」可言。
5. **改完要回報改之後的實際值**（從系統再讀一次），不是回報「已送出」。

## 盤點與計畫

「讀」「改」欄：✓ 有；— 本質唯讀；**粗體**是要補的；（面板）是 Android 只准打開開關畫面。

## Android 的限制（Android 16，minSdk 與 targetSdk 都是 36）

- **直接可改**：鈴聲模式與音量（`AudioManager`；改到靜音或從靜音改回時牽涉勿擾，用通知讀取的權限）、手電筒（`CameraManager.setTorchMode`，不需權限）。
- **要「修改系統設定」（`WRITE_SETTINGS`，使用者在系統頁面允許）**：亮度、自動亮度、自動旋轉、自動關螢幕時間。
- **不准 app 改，只能打開開關畫面**：Wi‑Fi、藍牙、行動數據、飛航模式、定位、NFC、省電模式。
- **讀 Wi‑Fi 名稱**：要精確位置權限且定位開著，否則系統回 `<unknown ssid>`。

## 階段 1 的結果（2026-10-26，S24）

`sound`、`display`、`flashlight`、`connections` 在「手機控制」工具組（原生端 `PhoneStatePlugin`）；`device_info` 多了 `wifiName`。

- 直接呼叫 plugin：鈴聲改響鈴 40% 再改回震動、手電筒開關、讀到 Wi‑Fi 名稱都正常。`display` 讀得到；改要先在 設定 › 手機 › 系統權限 › 修改系統設定 允許。
- 開關面板：NFC 關／開、藍牙關／開，連續三輪 12 次全部 `changed`，每次 0.4–1.5 秒，做完回到原本的 app。
  - 一開始第二次開面板時找不到開關（上一個面板還在關），改成只看使用中的視窗、等 3 秒還沒有就再開一次。
  - 藍牙是完整的設定頁，按返回會停在設定首頁：記下開面板前在前景的 app，做完回到它。
- 問一般的話（Claude Opus 5.5）：
  - 「現在把鈴聲打開，但不要太大聲」：`sound` 設鈴聲 30%（手機的刻度是 33%），12 秒。
  - 「藍牙關掉」：`connections`，17 秒，藍牙真的關了。
  - 「一連上當前 wifi，幫我把鈴聲打開，但不要太大聲」：這次 Bot 從 `device_info` 拿到「Zhao」，排程寫好「連上 Zhao 時把鈴聲設 30%」；卡在排程本身要位置「一律允許」（Android 規定背景讀 Wi‑Fi 名稱要它），系統權限頁停在畫面上，Bot 告訴使用者去哪裡開。這是既有的權限要求，不是這次的缺口。
- 測完把鈴聲改回震動、藍牙打開。
