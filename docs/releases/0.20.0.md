pi mobile 0.20.0：連到 CLIProxyAPI 時，Bot 每一步只上傳新增的部分；其他自訂端點的請求先壓縮再送。長對話的 Bot 更省電、更省流量。

> **非官方社群專案**：pi mobile 不是 [pi](https://pi.dev) 官方產品，與 Earendil 沒有關聯，也沒有經過他們背書。問題請回報到這個 repo。

## 下載
- **手機**：已經裝了 0.9.1 以後的版本，到設定頁最下面按「更新到 0.20.0」就好。也可以下載 `pi-mobile-0.20.0.apk`（或永遠指向最新版的 `pi-mobile.apk`）手動安裝。需要 **Android 16 以上**、arm64 手機。安裝檔用同一把金鑰簽章，可以直接覆蓋安裝，保留現有資料。
- **iPhone、iPad**：從 TestFlight 更新。
- **電腦**：這一版不用更新。

## 這一版有什麼
- **只上傳新增的部分**：模型接的是 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) 時，pi 改走它官方推薦給 pi 的路線（和電腦上的 pi 一樣），連續的對話和 Bot 的多步驟工作，每一步只送新的那一句或新的工具結果，不再把整段對話重傳一次。
  - 在 S24 上，一段帶著 45 KB 資料的對話，之後每一步從整包重傳降到約 10 KB。對話越長，省得越多。
  - Claude、GPT 都適用，提示快取照樣有效。
  - pi 會先確認對方真的是 CLIProxyAPI、而且記得前面的對話，才改走這條路；任何問題都會退回原本的方式，對話不受影響。
- **請求先壓縮再送**：其他自訂端點只要支援，送出的請求會先壓縮，文字大約小 2.5 到 4 倍。pi 會先確認對方讀得懂，不支援的照舊。

## 要注意
- **App 每次啟動後的第一則訊息**還是整包送，同時在背景確認，確認時會用你目前的模型送 2 次很小的請求。
- **閒置超過 5 分鐘**，連線會關掉，下一則再整包送一次。每小時一次的排程，第一步通常還是整包（但有壓縮）。
- 這條路線的 API key 放在連線網址裡（只在 Tailscale 這類加密通道內）；如果你開了 CLIProxyAPI 的請求記錄，記錄檔裡可能會看到它。
- **代你操作 App**：更新 App 後，Android 會把無障礙服務關掉，要到 設定 › 手機 › 代你操作 App 再開一次。
