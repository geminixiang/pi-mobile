pi mobile 0.8.0：手機斷網時電腦上的指令繼續跑、回來接著拿結果；改設定不再打斷進行中的工作；Bot 能讀和改手機的音量、螢幕、手電筒和連線。

> **非官方社群專案**：pi mobile 不是 [pi](https://pi.dev) 官方產品，與 Earendil 沒有關聯，也沒有經過他們背書。問題請回報到這個 repo。

## 下載
- **手機**：`pi-mobile-0.8.0.apk`，**Android 16 以上**、arm64 手機。用同一把金鑰簽章，可以直接覆蓋安裝 0.7.0，保留現有資料。
- **電腦**（選用，macOS 或 Linux，要裝好 Tailscale）：
  ```sh
  curl -fsSL https://raw.githubusercontent.com/geminixiang/pi-mobile/main/host/install.sh | sh
  ```
  已經裝過的話，跑同一行就會更新；配對和權限都保留，不用重新配對。

## 這一版有什麼
- **手機斷網，電腦上的指令照跑**：4G/5G 斷幾十秒到幾分鐘（進電梯、換基地台、關 Wi‑Fi）時，電腦上的 pi-env 和它跑的指令會留著等手機回來，最多 5 分鐘；手機回來後接上同一條連線，補送彼此沒收到的部分，指令的結果直接回到對話。Bot 面板的電腦狀態會顯示「重新連線中」。要電腦端也更新到 0.8.0 才有。
  - 實測：容器裡 240 秒的指令執行中把手機的 Tailscale 關掉 75 秒再開，24 行輸出一行不少。
  - 超過 5 分鐘、或 app 被系統殺掉，指令會被收掉，工具回「結果不明」。
- **改設定不再重開整個 agent**：預設模型、思考程度、壓縮門檻、電腦清單、預設電腦改了就直接生效，進行中的回合和電腦連線不受影響。以前改任何設定都會停下正在跑的工作（容器裡的指令會回 `Tool bash was interrupted`）。供應商金鑰、雲端憑證、GitHub token、行事曆範圍還是會重開。
- **手機狀態**：新工具讓 Bot 讀和改音量（鈴聲和五種音量）、螢幕（亮度、自動亮度、自動旋轉、逾時；要在 設定 › 手機 › 系統權限 允許修改系統設定）、手電筒，以及 Wi‑Fi（含目前的名稱）、藍牙、行動數據、飛航、定位、NFC、省電模式。Android 只允許 app 打開這些連線的開關：手機畫面有開的話 pi 會替你點、確認狀態、回到原本的 app；沒開就把開關留在畫面上給你。
- **電腦連線的狀態與錯誤**：
  - Bot 面板顯示每台電腦的連線狀態（連線中、已連線、幾點幾分斷線和原因）。
  - 連線在請求送出後才斷，工具回「結果不明，重試前先確認」，Bot 不會自己重跑 `git push` 這類指令；還沒送出就斷的，照常重試。
  - 選了容器的 Bot 只在真的用到電腦時才準備容器；打開面板或冷啟動不再連電腦。
  - 從設定移除電腦時，手機會同時撤銷那台電腦上的配對（電腦端要 0.8.0；舊版會提示手動刪）。
- **診斷記錄**：設定最下面「分享診斷記錄」把最近 2000 行（含主執行緒卡頓）存成 `.jsonl` 分享出去；金鑰樣式會先遮掉。正式版關閉了 WebView 偵錯，回報問題時附這個。
- **自訂供應商**：在 tailnet 裡的 gateway 建議用 `https://<電腦>.ts.net:<port>`（README 有一行 `tailscale serve` 設定）；連不到時會說要開 Tailscale，而不是「Load failed」。
- **其他**：pi-env 的電腦端執行檔改成壓縮後打包，APK 小約 4 MB；前景／背景切換時被中斷的資料庫交易會重試；工具依 app 啟動時找到的原生功能決定要不要裝。

## 要注意
- **Android 16 以上才能裝**：pi 只在一支 Android 16 的手機上測，舊版 Android 的分支拿掉了。0.7.0 之前的手機不會再收到更新。
- **電腦端也要更新**：舊版電腦端（0.7.0）配 0.8.0 的手機可以用，但手機斷網時指令還是會中斷，移除電腦時也不會撤銷配對。
- **手機畫面**：更新 app 後，Android 會把無障礙服務關掉，要到 設定 › 手機 › 手機畫面 再開一次。
- 排程漏掉的不會補跑：手機關機或 app 被殺掉而錯過的「每天幾點」排程，下一次照常跑，不會在開機後補一次。
